# Windows 微信红包本地助手：设计说明

**状态：** 已批准，MVP 实现计划已创建
**范围：** 个人使用、Windows、本机运行、微信窗口保持可见

## 1. 目标与边界

本项目是一个独立的 Windows 系统托盘工具。它在用户的微信桌面端保持登录、打开且不最小化时，通过屏幕上的可见界面识别红包，依次模拟点击红包卡片和领取页的“开”按钮，并确认本轮结束。

目标是减少用户对红包出现和领取步骤的手动关注，而不是修改、注入或逆向微信客户端。

### 目标

- 仅针对可见的微信窗口，自动完成一轮领取动作。
- 每个点击动作都由当前画面识别结果验证，避免基于绝对坐标的盲点。
- 用户能随时停止、限制群聊范围、限制运行时段和领取频率。
- 默认将图像、聊天内容和运行记录留在本机。
- 在识别不确定、页面不符合预期或超时时安全退出当前轮次。

### 非目标

- 微信窗口最小化、后台运行或未显示在屏幕上时的领取。
- 读取微信数据库、进程内存或网络通信，或向微信进程注入代码。
- 多账号、多电脑、云端控制或远程操纵。
- 绕过平台限制、验证码、风控提示或其他安全机制。

使用前应由用户自行确认该用途符合所使用微信版本及所在地区的服务规则；工具不尝试规避其限制。

## 2. 方案选择

### 已评估方案

1. **固定坐标连点**：实现最快，但会被窗口位置、缩放、界面改版和网络延迟轻易打断，不采用。
2. **客户端内部读取或注入**：可覆盖后台场景，但侵入性高、维护和账号风险高，不采用。
3. **前台窗口视觉识别 + 普通鼠标自动化**：需要微信可见，但可以在每一步验证界面，保持本机边界清晰。采用此方案。

### 前提条件

- 运行环境为 Windows，微信已登录并保持窗口可见，不能最小化。
- 用户允许工具获得必要的屏幕捕获和输入自动化权限。
- 初期支持一个约定的显示缩放比例和浅色主题；其他缩放比例、主题和微信界面版本通过样本回归测试后逐步支持。

## 3. 架构

```text
系统托盘与设置
        │
        ├───── 配置：白名单、时段、限额、紧急停止
        │
微信窗口观察器 ──> 屏幕捕获器 ──> 视觉识别器
                                      │
                                      v
                             红包状态机 / 决策器
                                      │
                         ┌────────────┴────────────┐
                         v                         v
                   鼠标执行器                 本地事件日志
                         │
                         v
                       微信窗口
```

### 模块职责

| 模块 | 职责 | 输入 | 输出 |
| --- | --- | --- | --- |
| 托盘与设置 | 展示运行状态、编辑规则、切换测试模式、响应停止热键 | 用户操作 | 运行配置、启停命令 |
| 微信窗口观察器 | 识别目标窗口是否可见、前台、尺寸正常且未被最小化 | Windows 窗口状态 | `WindowReady` / `WindowUnavailable` |
| 屏幕捕获器 | 仅采集微信客户区的当前图像，并附带坐标转换信息 | 有效窗口矩形 | 当前帧 |
| 视觉识别器 | 判断当前帧的界面状态，给出红包卡片、“开”按钮或完成/异常提示的位置与置信度 | 当前帧 | `RecognitionResult` |
| 状态机 / 决策器 | 将视觉结果和规则组合成下一步动作，负责超时、重试、去重和冷却 | 识别结果、配置、当前状态 | `Action` 或安全退出 |
| 鼠标执行器 | 在执行前再次确认窗口和目标，移动并单击；不执行键盘输入或客户端内部操作 | 可执行 `Action` | 成功、失败或取消 |
| 本地事件日志 | 记录动作与诊断信息，不记录聊天正文或完整画面 | 事件 | 可查看的本地记录 |

## 4. 状态机与数据流

```text
Idle
  └─[窗口有效且发现红包候选]→ Candidate
Candidate
  └─[置信度、白名单、频率检查通过]→ ClickEnvelope
  └─[任一检查失败]→ Idle
ClickEnvelope
  └─[点击成功且领取页出现]→ AwaitOpen
  └─[超时 / 界面不符]→ Abort
AwaitOpen
  └─[“开”按钮识别稳定]→ ClickOpen
  └─[超时 / 已被领取 / 异常页]→ Abort
ClickOpen
  └─[结果页或会话页确认]→ Cooldown
  └─[超时 / 界面不符]→ Abort
Cooldown / Abort
  └─[记录原因、等待冷却]→ Idle
```

每一个从状态机发出的点击动作必须满足以下条件：

- 微信目标窗口仍处于前台、可见且客户区尺寸未变化。
- 最新一帧仍识别到与当前状态匹配的目标；不使用上一次帧的旧坐标。
- 目标置信度高于设定阈值，且在短时间内连续帧一致。
- 未触发全局停止、运行时段、群聊白名单、单轮超时或次数上限。

动作后状态机不依据“已点击”推断成功，必须等待画面变为下一预期状态。所有不匹配都转为 `Abort`，而不是尝试额外点击。

## 5. 视觉识别策略

识别层采取由轻到重的组合策略：

1. 在微信客户区查找稳定的视觉锚点，缩小候选区域。
2. 对红包卡片和领取页按钮做图像特征/模板匹配，得到候选矩形与置信度。
3. 仅在候选接近阈值或需要区分相似页面时，以本地 OCR 读取少量界面文字作为二次确认。
4. 用连续两到三帧的一致结果才允许点击，降低滚动、动画和弹窗造成的误操作。

坐标保存为相对微信客户区的比例坐标，并在每一帧转换为当前屏幕坐标，因而不把窗口在屏幕上的位置当成不变条件。

首版不支持自动滚动找红包、不点击搜索结果、不处理未知弹窗或安全验证。遇到这些页面时只记录和提醒用户。

## 6. 控制、隐私与故障处理

### 用户控制

- 托盘菜单展示“停止 / 仅检测 / 自动领取”三种状态。
- 提供全局紧急停止热键；触发后立刻取消待执行动作并进入仅检测或停止状态。
- 可配置允许的会话白名单、运行时间段、每轮冷却间隔、每日领取上限和连续失败上限。
- **测试模式**只展示候选框、置信度和本应执行的动作，永不发送鼠标点击。

### 隐私

- 所有分析在本机完成，不建立网络服务或遥测上传。
- 默认日志仅保留时间、状态、置信度区间、动作结果和错误码。
- 调试截图默认关闭；如用户显式开启，截图保存在本机指定目录并可一键清理。

### 异常策略

- 窗口丢失、最小化、前台变化、尺寸变化：取消本轮。
- 识别置信度不足、未知页面、目标移动：不点击，等待或结束本轮。
- 页面加载超时、连续识别失败、点击后无预期变化：记录原因，进入冷却。
- 多次连续失败：自动降级为“仅检测”并提示用户复核界面样本。

## 7. MVP 范围与验收

### 开发顺序

1. 实现目标微信窗口检测、客户区截图与本地状态显示。
2. 建立样本集，完成红包卡片、领取页和完成/异常页的离线识别与回归测试。
3. 实现状态机、白名单/限频规则、日志和测试模式；在真实桌面环境中只画框、不点击。
4. 接入受控鼠标单击，在有限场景中验证“点击前确认、点击后验证、失败即退出”。
5. 完善托盘设置、紧急停止、异常降级，并对不同缩放比例和主题重复回归测试。

### MVP 验收标准

- 工具只在微信窗口可见且满足规则时产生候选动作。
- 测试模式能够显示状态、候选区域和“不点击”的决策原因。
- 自动模式的每次点击都有对应的前置识别记录和后置界面验证。
- 任何未知或低置信度页面都不会触发点击。
- 停止热键在等待与执行前两个阶段都能阻止后续动作。
- 断网、窗口最小化、窗口切换或页面加载过慢不会触发额外点击。

## 8. 后续决策

开始实现前需要根据用户实际环境确认：微信桌面端版本、显示缩放比例、浅色/深色主题、典型红包出现位置及需要支持的会话范围。这些信息用于建立本地测试样本和第一版识别阈值，而不扩大功能范围。
